探究模型内容生成的三层机制及优化方法

发表于2026-09-15|更新于2026-09-15|Finish

模型拦截三层机制

以Gemini为例，探究模型内容生成的三层机制及优化方法（供大家诊断）

先说结果，目前最好吃的是Gemini 3.7 Flash（temp=0.8, top_p=1, top_k=30）

（欢迎大家分享好吃的预设/参数，主播会逐个尝试与优化）

拦截机制分层

层 问题 原因 控制权 优化方法
L1:模型输入端 无正文，耗时 ~1 秒。HTTP 200 ，但 SSE 流无 content，error 帧返回 PROHIBITED_CONTENT prompt到达模型之前就被屏蔽了 模型提供商（e.g. Google） ❌ NO（换厂家/优化prompt）
L2:模型层 正文输出”我不能协助…”，finish_reason=stop 模型拒答 训练时植入 ⚠️ 可用预设（role: system）/越狱绕过（role: user）
L3:安全设置（输出级） finish_reason=SAFETY，受 HARM_CATEGORY 控制（一般出现在闭源客户端，开源的SillyTavern 默认全部OFF） 模型输出后被屏蔽 开发者可以配置 ✅ Yes, set HARM_CATEGORY_* to OFF

NSFW 生成能力

模型 能否生成 拦截层 中文质量 正文字数 首字延迟 备注
deepseek/deepseek-v3.2 ⚠️ 裸请求拒，配预设可过 L2（模型对齐） ★★★★★ 546 10.7s 中文最好；带系统提示后正常生成
google/gemini-3.7-flash ⚠️ 裸请求拒，配预设可过 L1（平台拦截） — 0 — 无
z-ai/glm-4.6 ⚠️ 裸请求拒 L2（模型对齐） ★★★★ 0（裸请求） 12.2s 智谱，中文母语；待用完整预设复测
cognitivecomputations/dolphin-mistral-24b-venice-edition ✅ 零拒答 无拦截 ★★★ 480 6.9s 去审查版；中文尚可但不如 DS/GLM
sao10k/l3.3-euryale-70b ✅ 零拒答 无拦截 ★★ 871 117.3s RP 文笔好但中文人名漂移、一致性弱；极慢

模型降级策略：默认用便宜快的模型（如 Gemini），检测到 L1 拦截时自动切换到宽松模型（如 DeepSeek）。用户无感，成本可控。

措辞路由：直白命令式最易触发 L1；叙事铺陈、感官推进更易通过。产品侧可以在用户输入和模型之间加一层请求重写。

测试环境：SillyTavern + OpenRouter，2026-08-24。模型版本和 API 行为可能随时间变化，建议用本文的方法论自行复测。
